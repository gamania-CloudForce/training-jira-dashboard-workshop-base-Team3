## 基於痛點的 User Story

### 痛點
> 作為工程師，我希望可以看到專案整體進度，以便我可以調整各項任務的timebox

## User Stories

### US-101: 專案整體進度檢視
**作為工程師**，我希望能在 Jira Dashboard 上即時檢視專案的整體進度百分比和里程碑狀態，以便我可以根據專案進度調整各項任務的時間分配。

**價值說明**: 透過了解專案整體進度，工程師能更好地規劃個人工作時程，避免因不了解大局而造成時間分配不當。

### US-102: 任務時程視覺化
**作為工程師**，我希望能在儀表板上看到所有任務的時程安排和相互依賴關係，以便我可以合理調整各項任務的 timebox 來配合專案整體節奏。

**價值說明**: 視覺化的時程安排幫助工程師理解任務間的關聯性，做出更明智的時間分配決策。

### US-103: 進度落後預警
**作為工程師**，我希望當專案進度落後預期時能收到即時通知，以便我可以重新評估並調整手上任務的優先順序和時間安排。

**價值說明**: 及早發現進度落後問題，讓工程師能主動調整工作策略，避免專案延期。

### US-104: 個人任務與專案關聯
**作為工程師**，我希望能清楚看到我的個人任務如何影響專案整體進度，以便我可以更有效地安排各項任務的 timebox。

**價值說明**: 了解個人工作對專案的影響程度，幫助工程師做出更有責任感的時間管理決策。

"## User Story

**US-001**: 作為產品經理（PM），我希望能在 Jira 儀表板上即時查看專案的整體進度與預計完成時間，以便能有效掌握專案狀態並及早調整計畫，確保專案如期完成。

### 驗收標準（Acceptance Criteria）
- 能在儀表板上清楚看到專案目前的進度百分比。
- 顯示預計完成日期，並根據進度自動更新。
- 若進度落後，儀表板會以顏色或提示標示。
- 支援多專案切換，PM 可快速檢視不同專案狀態。

### INVEST 原則檢查
- **V（Valuable）**：對 PM 有明確專案控管價值 ✓
- **T（Testable）**：可根據進度顯示、完成時間、提示等條件驗證 ✓
- **S（Small）**：可於一個 Sprint 內完成
- **I（Independent）**：可獨立開發
